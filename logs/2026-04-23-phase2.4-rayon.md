## Interpretation

**~10× out of 16 cores is about what you get from rayon on small tasks.**
Every tile is ~10 μs of work on the scalar kernel — small enough that
thread dispatch overhead, cache migration, and memory BW contention all
chip into the ideal 16× ceiling. P+E core asymmetry on Apple Silicon
also caps speedup: the 6 efficiency cores run at roughly half the
throughput of the P cores.

The rayon pattern here is textbook: `par_chunks_mut` on the output +
`par_chunks` on all three inputs, zipped, with `for_each` running the
per-tile kernel. Each worker has self-contained stack buffers (no heap
allocation inside the tile) which is exactly what rayon wants.

**Rayon beats SIMD by 8× on this workload.** That shouldn't surprise:
we have 16 cores and our 2-wide SIMD only attacks ~30% of per-tile
work. Different axes of parallelism, different payoffs; the interesting
experiment is what happens when you compose them (Phase 2.5).

## Notes on "fairness" of this comparison

Rayon's per-tile wall-time drops because work runs concurrently; SIMD's
per-tile wall-time drops because each tile does less work. These aren't
symmetric metrics — rayon's throughput gain needs a big enough batch to
amortize thread dispatch, while SIMD's gain applies at any batch size.
For small batches (B = 8, say) SIMD still wins; rayon's dispatch
overhead dominates.

Worth a follow-up: batch-size sweep. Current test only measures B=1024.
At B=16, rayon probably breaks even or loses; at B=64, pulls ahead;
at B=1024, dominates.

## What's next

Phase 2.5 — compose SIMD + rayon into a single
`mma_f32_out_batched_simd_rayon` entry. Naive expectation:
**1.25 × 10 ≈ ~12× over scalar batched**, or ~850 ns/tile
(≈11000× over oracle). But:

- Cache pressure doubles: each thread now runs the SIMD kernel, which
  has a slightly larger hot footprint (`i64x2` accumulators, NEON
  intrinsic code sequences).
- Apple M-series P cores already have wide scalar int dispatch; the
  SIMD kernel's theoretical win is partly being captured by the scalar
  core's own execution width even in the single-threaded case. When we
  add rayon, the extra cores are E cores (slower), which might SIMD
  less efficiently.

So the combined number could land anywhere from ~8× to ~12× over scalar
batched. Only way to know is to measure.
